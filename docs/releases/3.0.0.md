# draw-things-control 3.0.0

Version 3.0.0 moves generation behind one persistent local server. The CLI, terminal UI, HTTP API, and MCP server now share a durable queue while `dtc serve` remains the only process that starts `draw-things-cli`.

## Versioning note

Version 2.0.0 was intentionally skipped to reserve the major-version boundary for this server- and agent-facing release.

## Highlights

- **Persistent queue**: submit, monitor, cancel, resume, park, and hold chained jobs. Queue state survives restarts, and `dtc queue add --wait` follows a job to completion.
- **Agent interfaces**: an authenticated HTTP API and `dtc mcp` over stdio or Streamable HTTP provide typed tools for jobs, inputs, queue control, history, and guarded job-file writes.
- **Safer automation**: bounded inputs, path confinement, opt-in writes, recoverable job-file changes, caller-aware controls, and an audit log protect the agent-facing surface.
- **Unified CLI and TUI**: `dtc generate` submits bounded one-off work to the queue, the TUI shows live queue and generator output, and execution history can be filtered and deleted.
- **Video fidelity**: video jobs default to ProRes 4444, preserve stream color metadata, measure color drift, and can apply region-aware correction across a chain.

## Breaking changes since 1.0.0

- Start `dtc serve` before generating or submitting jobs; direct chained execution is removed.
- Replace `dtc run-job JOB` with `dtc queue add JOB --wait`.
- `dtc generate` is now a queue client: outputs must be relative paths inside the configured output directory, and only its bounded local option set is accepted.

## Requirements

Python 3.12+, [uv](https://docs.astral.sh/uv/), and `draw-things-cli`. Install with `uv sync`, start the server with `uv run dtc serve`, and see the [user guide](../user-guide.md) for queue, API, TUI, and MCP setup.
