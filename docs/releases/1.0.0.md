# draw-things-control 1.0.0

First stable release of `draw-things-control`, built for long-horizon video generation by autoregressive image-to-video chaining: each run starts from the previous run's output, and the Draw Things app does the generating underneath through the locally installed `draw-things-cli`. It is a Python 3.12 CLI and terminal UI.

## Highlights

- **`dtc generate`**: generate a single image or video, with `--dry-run` to preview the command.
- **Chained YAML jobs** (the core of the release): `dtc validate-job` and `dtc run-job` run a chain of image-to-video generations, each starting from the previous output, with prompt pairs, configuration overrides, input resizing, and automatic or manual cooldowns.
- **Terminal UI** (`dtc tui`): browse jobs, run and watch them live, inspect status and execution details, and review past runs.
- **Run history and lock**: executions are recorded in a local SQLite store, and a run lock keeps to one `draw-things-cli` at a time. `dtc import-history` brings in phase 1 job manifests.
- **Clean layers**: `cli`/`tui` over `services`, `state`, `jobs`, and `core`, with the import direction, size limits, and pyright checked in `make check`.

## Breaking changes since 0.1.0

- `generate` and `validate-config` read YAML configurations only.
- Job files and the global configuration are read strictly; old key and command hints are dropped, except for `cooldown_seconds`.
- The `/jobs`, `/job`, `/history`, `/execution`, and `/run` hints in the TUI are gone; each is now an unknown command.

## Requirements

Python 3.12+, [uv](https://docs.astral.sh/uv/), and `draw-things-cli`. Install with `uv sync` and run `uv run dtc --help`.

The API and MCP servers (Phase 3) are not part of this release.
