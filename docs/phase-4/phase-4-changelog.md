# Phase 4 changelog

Owner decisions, design decisions, and notable changes for
[Phase 4](README.md). Newest first.

## 2026-10-20

- **Design decision** [M15]: Tighten search selection to at least a 1% relative training-error gain and its aggregate promotion interval from 90% to 99%. After the approved-prior fit was corrected, the 120-execution no-change control selected `half_life_runs` for a 0.07% training gain and accepted one of 13 searches on a held-out gain of about 0.01 to 0.04 percentage points; the relative floor rejects that noise-sized selection before opening holdout, while the focused deterministic case's 2.47% training gain remains eligible. The wider interval addresses repeated held-out looks. With both guards, the shifted and no-change 120-execution controls each left all 13 searches unchanged. The ordinary calibration gate, coverage veto, and per-group regression checks retain their planned 90% interval. An absolute one-percentage-point gain was rejected because it also rejects the focused case's repeatable but smaller held-out improvement.

- **Change** [M15]: The completion review corrected validated calibration to fit coefficient deltas around the approved prior, so repeated updates no longer pull an already-correct shift, structural term, knob effect, or size offset back toward zero. It also distinguishes a valid but too-small replay from an invalid candidate, validates every cross-group search calibration before opening holdout or staging any approval, and makes rollback restore the earlier approval provenance while retaining current learning counters. Reusing each candidate's parsed training rows across leave-one-execution-out folds reduced the prepared 300-run full search to 3.97 CPU seconds and restored margin under the unchanged 10-second cap. The two fixed-work CPU-budget checks run serially after the eight-worker functional suite so concurrent load cannot change the machine-speed contract they measure.

- **Change** [M15]: Milestone 15 is done. Later calibration updates now fit against the approved prior with training-only penalty selection, replay the full remaining-time forecast on unseen executions, gate both error and distance from 80% coverage, and restore a clearly regressed live provisional calibration independently of candidate validity. The guarded cross-group search runs every 20 new complete runs when a group has 40 runs from six executions, chooses one adjacent unpinned tunable using training executions, opens the later holdout once, and writes the searched tuning, refitted calibration, and `validated.json` in one transaction only for a strict gain with no coverage or group regression. `tune`, `show`, `check`, reset, rollback, cancellation, the 10 CPU-second cap, and the evaluation and performance evidence are complete; the earlier entry saying full selection remained in progress is superseded.

- **Design decision** [M17]: Treat “comprehensive” as a review of every package followed by selective, evidence-backed edits, not a requirement to rewrite every area. Execute the cleanup in risk order from test support and local simplifications through parsing, compilation, H3 finishing, execution state, queue coordination, and the completed timing subsystem. Maintain and remove tests inside the production slice whose contract they protect, with an explicit stop rule against abstractions that only move code or obscure execution order.

- **Design decision** [M14]: A checkpoint's calibration is fitted from the ring against the factory each time, not stacked on the previous fit, so it is a function of the ring, the factory and the pins and a rejected candidate costs nothing later. - **Design decision** [M14]: The per-signature summaries the calibration keeps (top 40 per pipeline: count, executions, last seen, median step, median stage seconds) are consumed as tier 1 when history holds nothing for a signature: three runs from two executions, as history asks. - **Design decision** [M14]: The ring takes numeric and boolean run knobs, fixed enums and fixed labels only; a text-valued knob and a reference pair's name are not recorded, so such a knob cannot become a learned effect (it still separates signatures in history). `rollback N` puts the files back as they were before the Nth most recent update, as a set, in a transaction of its own (journaled and backed up, so it can itself be rolled back) with that time's record of what the machine wrote; it keeps the ring and the completed-run counts, so learning resumes at the next checkpoint and does not redo the one just undone. `reset` removes the file in one transaction (a copy stays in the backups), zeroes its groups' counts, and the ring is replayed through the checkpoints on the next update. A malformed or newer file does not advance its groups' counts, so the checkpoints it missed are reported as deferred by `check` and are not lost.
- **Design decision** [M14]: Two guards the specification implies. An update records the digest of each file as it read it and, when it is about to replace one, stops the whole update if the file has changed since, logs why, and leaves the edit to be read as a pin by the next update, as the milestone asks. The ring also records the host's load at each run's start (three numbers), which the out-of-scope thermal and load modeling can use later.
